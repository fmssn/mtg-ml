# Handoff: native engine, rollout pipeline, network size (2026-10-06)

Read this first in the next session. It summarizes what PR #3 changed, what is measured, what is still open and the gotchas. Details are in the linked docs.

## State of the repo

- **Rust engine** (`native/`, module `mtg_ml_native`). It plays exactly the same games as the Python reference: same RNG, same decision order, labels, keys, observations and full hidden state. Select it with `--engine native`, `engine=` or `MTG_ENGINE=native`; Python is still the default. Build: `cd native && maturin develop --release`. See [native-engine.md](native-engine.md).
- **Differential testing**: `pytest tests/test_difftest.py` (fast), `python -m mtg_ml.difftest fuzz --games 5000 --jobs 8` (long). All rules, card, bot and fuzz tests run on both engines (`tests/conftest.py`). 424 tests pass. More than 10k fuzz games have been played with no divergence.
- **Card pool** is a declarative spec, `mtg_ml/engine/cards.toml`, loaded by both engines. How to add cards and decks: [adding-cards.md](adding-cards.md) (worked example: Vapor Snag, which is in the pool but in no decklist).
- **Rollouts**: samples come back packed (`rl/samples.py`, `collate_packed`). Unpickling them used to cap all rollouts at ~150-200k decisions/s.
- **Inference**: `--inference local` (default: CPU torch in each worker) or `--inference server` (a central GPU process; workers never import torch). See [inference-server.md](inference-server.md).
- **Network**: training defaults are now **hidden 512, MLP trunk, separate value net**. `--trunk transformer` exists but is not practical yet. Old checkpoints still load.

## Numbers that matter (h100-private, 60 workers, one H100)

| decisions/s | local inference | GPU server |
|---|---:|---:|
| h128 MLP, shared value (old default) | 558k | 334k |
| h512 MLP, separate value (current default) | 153k | 291k |
| h512 transformer | 5k | 30k |

- Single core: engine 21.6× faster than Python; rollout CPU path 12.6×; scripted-bot games 3.5×.
- One training iteration (2048 games) at the current default: 4.7 s rollout + **19.8 s PPO update**. The update is now the bottleneck.
- Recommended command: `OMP_NUM_THREADS=8 python -m mtg_ml.rl.train --engine native --inference server --device cuda --games-per-iter 2048 ...`

## Open work, in order

1. **Does 512 play better than 128?** Nothing has been measured yet. Train both for the same number of decisions and compare the score against the scripted bots (`rl.evaluate CKPT bot --bo3`) and against pool checkpoints. This decides the default network size and the inference mode (at hidden 128, local inference is faster).
2. **Speed up the PPO update** (19.8 s per iteration at h512). Profile `rl/ppo.py`; likely candidates: collate per minibatch, the packed-sequence GRU replay, mixed precision, larger minibatches.
3. **Server per-batch overhead** (~8.7 ms per ~1,800-decision batch, mostly launch and preparation overhead, not compute): CUDA graphs, fusing the two policies' batches. Profile with `tools/profile_server.py`.
4. **Transformer trunk**: needs mixed precision and one token per object instead of one per hashed feature (100-250 tokens per decision today) before it is worth training.
5. Optional: Rust writes requests and samples straight into the shared buffers (the remaining Python packing in workers); per-decision memoization in the scripted bots, which are ~70% of a bot game.

## Tools

- `tools/bench_engine.py`: engine-only, agents, rollout CPU path and bots; single process or many pinned processes.
- `tools/bench_rollout.py`: end-to-end rollouts. Options: `--inference local|server`, `--dry-run` (skip the network), `--hidden/--trunk/--value-net`, `--server-cpus/--worker-cpus`.
- `tools/profile_server.py`: the server's batch processing in isolation. `MTG_SERVER_PROFILE=/tmp/x.prof` profiles a live server.
- `python -m mtg_ml.trace check`: golden digests of the reference engine; regenerate only for intentional rules changes.

## Gotchas

- **h100-private GPU at PCI 0000:be:00.0** (index 6 when all 8 are listed) fell off the bus on 2026-10-06 and took CUDA down for every process, which needed a reboot. Never use it. Select GPUs by UUID, e.g. `CUDA_VISIBLE_DEVICES=GPU-7676f9cf-4831-a790-93c2-35f5313164c4` (bus 87). ComfyUI runs as `comfyui.service` on GPUs 2 and 3.
- The box is shared. Pin CPU work (`taskset`, `--cpus`, `--worker-cpus`), check `uptime` and `ps` first, and never `pkill -f` a broad pattern. Branch copy: `~/mtg-ml-native`; the venv `~/mtg-ml/.venv` has the `mtg_ml_native` wheel; Rust is in `~/.cargo/bin`, PyPy 3.11 via `~/.local/bin/uv python find pypy3.11`.
- On the box, always set `OMP_NUM_THREADS` (8 for training, 2 for the server), or the PPO update hangs on 64 threads.
- After changing Rust code, rebuild **and reinstall** the wheel (`maturin build` + `pip install --force-reinstall`) on every machine you run on. `tests/test_difftest.py` catches a stale build only if it diverges.
- `PolicyNet` constructor defaults are the old ones (128, shared value), for checkpoint compatibility; the new defaults live in `TrainConfig`.
- Learnings from this session: measure before recommending infrastructure. The GPU server was proposed before checking how cheap CPU inference was; the real cap turned out to be sample unpickling.
